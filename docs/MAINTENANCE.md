# Profile README maintenance

## Artwork

All artwork lives in `docs/assets/` and is generated by `build_assets.py` and its `atlas_plates.py` helper (Python 3, standard library only):

```bash
python3 docs/assets/build_assets.py
```

| File | Used for |
|:--|:--|
| `hero-dark.svg`, `hero-light.svg` | Header, switched by `<picture>` on the viewer's color scheme |
| `domains-dark.svg`, `domains-light.svg` | Previous three-domain banner, retained as legacy artwork |
| `footer-dark.svg`, `footer-light.svg` | Closing graphic |
| `atlas-launch-{light,dark}.svg`, `atlas-launch-mobile-{light,dark}.svg` | Linked Atlas launch plate, with mobile and desktop layouts |
| `sourcesnap-trace-{light,dark}.svg`, `sourcesnap-trace-mobile-{light,dark}.svg` | SourceSnap architecture linked to its repository, with a separate Atlas inspection link |
| `shoemaker-trace-{light,dark}.svg`, `shoemaker-trace-mobile-{light,dark}.svg` | Sequential planning, execution and review linked to the repository, with a separate Atlas inspection link |

The original header and footer use commit-pinned [jsDelivr GitHub URLs](https://www.jsdelivr.com/?docs=gh), which GitHub serves through its Camo image proxy. This avoids direct raw.githubusercontent.com requests that failed during live browser verification. The editable source stays in this repository. The new Atlas plates use `/readme/` URLs on the deployed companion site; the native Domains bullets replace the previous domains banner.

Each new plate uses two linked `<picture>` elements, one per theme. Their outer link URLs end in GitHub's [theme context fragments](https://github.blog/changelog/2021-11-24-specify-theme-context-for-images-in-markdown/), `#gh-dark-mode-only` or `#gh-light-mode-only`, so GitHub hides the inactive link and its image. Inside each picture, a width-only `(max-width: 600px)` source chooses the mobile layout and the fallback image provides the desktop layout. Keep theme fragments on the outer links: GitHub's current theme visibility CSS selects link `href` suffixes. Putting them only on the image does not hide an image that is already inside a custom link.

Do not combine width and `prefers-color-scheme` in the new plate source queries. GitHub's `themed-picture` script rewrites theme sources to always match or never match for pinned themes, discarding a compound width condition. The original theme-only header and footer sources remain valid. Keep separate native Atlas inspection links for the project plates so theme fragments do not alter the app's `#project/...` routes. Verify desktop and mobile image selection in the live GitHub page after publishing; the Markdown API preserves source queries without executing that script.

After changing original artwork, regenerate it, publish the asset commit, then update the six original README image/source URLs to that commit SHA. Keep the full commit SHA in each URL so cached images are immutable. After changing Atlas plates, rebuild and deploy the site before publishing their README references. Add the new asset commit SHA as a `?v=<sha>` query to the changed plate URLs so GitHub requests fresh Camo images. Verify both themes and mobile variants through GitHub Camo.

To change colors, edit the `THEMES` palette at the top of the script. To change text inside a graphic, edit the matching function (`hero`, `domain_card` and `DOMAIN_CARDS`, `footer`) and regenerate. Keep these rules so GitHub renders the files safely:

- No scripts, `foreignObject`, external fonts, external images or links inside SVGs.
- Motion is CSS only, starts from a readable static frame, and is turned off under `prefers-reduced-motion: reduce`.
- Every SVG has a `<title>` and `<desc>`, and every README image has alt text. Anything important in an image also appears as Markdown text.

The older files in the top-level `assets/` folder are no longer referenced and are kept only so the previous design can be restored.

## Systems Atlas

The companion is a static HTML, CSS and ES module site in `docs/atlas/`, with no runtime package dependencies or external API calls. `src/content.js` contains the curated entries, conceptual relations and illustrative routing devices. Keep the initial HTML index, research text and contact links in sync so the sources remain usable without JavaScript.

From `docs/atlas/`, using Node 24 or later:

```bash
npm test
npm run build
```

The build creates ignored `dist/` containing only the public runtime files, `vercel.json`, and generated SVG artwork under `readme/`. It excludes tests, maintenance notes, source generators and private evidence. Upload the contents of this directory as a separate static Vercel project, with `index.html` at its root. Keep the security headers in `vercel.json` effective after deployment.

Production: [Systems Atlas](https://chinmay-systems-atlas.vercel.app/), the `chinmay-systems-atlas` project in the owner's personal Vercel workspace. The initial release used Vercel's Drop to Deploy with the reviewed 37-file static output. Future releases should deploy the rebuilt output to this same project. The existing portfolio remains at `https://chinmayshringi.web.app/`.

Verify public HTTPS access, the effective application and artwork security headers, all twelve new artwork URLs and GitHub's Camo-rendered profile images before publishing changed links. The application policy permits only same-origin runtime resources; the authored SVG policy permits inline styles and sandboxes direct document views.

Verify search by full publication title, filters, keyboard selection, Back/Forward, project hash links, copied entry links, palette commands, routing exclusions, and theme/motion preferences. At mobile and tablet widths, selecting an entry should reveal its inspector below the index. Confirm that the measured sticky masthead does not cover focused headings, and that reduced motion and the no-JavaScript source links remain usable.
